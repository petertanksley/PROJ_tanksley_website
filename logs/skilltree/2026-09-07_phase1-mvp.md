## Second revision: ternary → hexagonal year rings (Peter's idea)

Peter proposed axes emanating from a central origin with year bands encircling it, hexes strung along
their year band at a position set by their area scores. I amended triangular bands to hexagonal rings
so the hex lattice does the collision handling (ring k has 6k cells) and the whole thing stays a
honeycomb. He chose hexagons. This restores time as a layout axis, which the ternary had lost, and
keeps the area geometry: three axes 120° apart through alternating ring corners, direction = vector
sum of the 0–3 ratings.

## Hover: spin → coin flip (Peter caught it)

Peter: rotating the images "will make them land at weird angles"; asked for darkened-at-rest hexes
that flip like a coin into view on hover/select. Correct — a 60° rotation shows real sticker art
sideways for the whole hover. Replaced with: stickers dimmed at rest (`brightness(0.42)
saturate(0.55)`, muted tier also greyscale), and on hover a 460 ms 2-D flip (`scaleX` squeezed to 0.04
at the midpoint, image lighting switched there with `steps(1)`), landing face-up at 1.18×. No 3-D
transforms: CSS `rotateY` on SVG elements is unreliable across browsers. Leaving fades back to dim;
pin holds the lit state and pulses the ring; focus flips too. Placeholder colour lightened to
#6E6A80 so it still reads once dimmed. Verified: rest transform none / filter dim; mid-flip transform
matrix(0.08, 0, 0, 1.12); settled matrix(1.18, 0, 0, 1.18) with filter none; after leave back to dim.

## Real-browser bugs in the flip (Peter caught both)

Peter: "None of the placeholders are rendering and the coinflip is continuous and rapid." Both were
invisible in headless Chrome, which passed every check.

1. **Images vanished** because the resting dim was a CSS `filter` on SVG `<image>` elements. Headless
   (software-rendered) Chrome draws it; GPU-composited Chrome and Safari drop the image. Replaced by a
   plain filled hexagon (`hex-shade`) drawn over the image, opacity 0.66 at rest → 0 when lit. No
   filters on SVG images anywhere now.
2. **The flip looped** because on every `mouseenter` I re-appended the node to paint it on top. Moving
   an element in the DOM restarts its CSS animation and, in a real browser, re-fires mouseleave /
   mouseenter under a moving pointer, so the flip restarted continuously. Removed the hover reorder
   (only a pin/click raises now) and made the flip self-contained: `flipping` and `lit` are added
   together, the animation runs once with `both` fill, nothing depends on `animationend`.

Also: `fetch(..., {cache: 'no-store'})` so the dev preview never serves a stale `tree.json`; and
`quarto render` while `quarto preview` runs races over `.quarto/_freeze` — stop the preview first.
Verified after the fix: 30 images drawn, one `st-flip` animationstart during 1.2 s of pointer jitter,
shade 0.66 → 0 → 0.66 across hover/leave.
